# JSON Recorder & Auto Runner
一个用于**Windows 软件 UI 自动化测试**的鼠标录制与回放工具。
本项目包含两个独立程序：
- `json.exe` —— 鼠标操作录制器
- `auto.exe` —— JSON 操作回放器
> 仅用于软件测试、UI 自动化和重复操作测试。

一、json.exe

功能

json.exe 用于记录鼠标点击操作，并将操作保存为 JSON 文件。

支持两种录制模式：

JSON1

用于记录一次性执行的前置操作。

例如：

启动软件
↓
进入指定页面
↓
点击菜单
↓
点击按钮
↓
进入需要循环操作的页面

最终保存为：

json1.json

⸻

JSON2

用于记录需要重复执行的操作。

例如：

点击输入框
↓
点击按钮
↓
点击确认
↓
返回

最终保存为：

json2.json

⸻

使用方法

打开：

json.exe

选择：

json1

然后点击：

开始录制

操作目标软件。

完成后点击：

停止录制

然后点击：

导出 JSON

保存为：

json1.json

⸻

录制 JSON2

重新打开 json.exe。

选择：

json2

点击：

开始录制

执行需要重复的鼠标操作。

完成后：

停止录制
→
导出 JSON

保存为：

json2.json

⸻

二、JSON 文件格式

基本格式：

{
  "version": 1,
  "mode": "json1",
  "window": null,
  "events": [
    {
      "type": "click",
      "x": 520,
      "y": 340,
      "button": "left",
      "delay": 0.82
    }
  ]
}

字段说明

version

JSON 数据版本。

"version": 1

⸻

mode

当前 JSON 类型。

JSON1：

"mode": "json1"

JSON2：

"mode": "json2"

⸻

window

记录录制时活动窗口的基本信息。

例如：

"window": {
  "title": "Example",
  "left": 100,
  "top": 100,
  "width": 800,
  "height": 600
}

如果无法获取窗口信息，则可能为：

"window": null

⸻

events

鼠标事件列表。

例如：

"events": [
  {
    "type": "click",
    "x": 520,
    "y": 340,
    "button": "left",
    "delay": 0.82
  }
]

⸻

x / y

鼠标点击位置。

"x": 520,
"y": 340

表示屏幕坐标：

X = 520
Y = 340

⸻

button

鼠标按键。

支持：

left
right
middle

例如：

"button": "left"

表示鼠标左键。

⸻

delay

距离上一次点击的等待时间，单位为秒。

例如：

"delay": 0.82

表示等待约：

0.82 秒

再执行当前点击。

⸻

三、auto.exe

功能

auto.exe 用于读取 json1 和 json2，按照指定顺序自动执行鼠标操作。

执行流程：

JSON1
  ↓
完成 JSON1
  ↓
JSON2 第 1 次
  ↓
JSON2 第 2 次
  ↓
JSON2 第 3 次
  ↓
……
  ↓
达到指定次数
  ↓
结束

⸻

四、auto.exe 界面

程序包含三个主要输入：

输入框 1：JSON1

将完整的 json1.json 内容复制到第一个输入框。

例如：

{
  "version": 1,
  "mode": "json1",
  "events": [
    {
      "type": "click",
      "x": 520,
      "y": 340,
      "button": "left",
      "delay": 0.82
    }
  ]
}

JSON1 只执行一次。

⸻

输入框 2：JSON2

将完整的 json2.json 内容复制到第二个输入框。

JSON2 会在 JSON1 完成以后开始执行。

⸻

输入框 3：循环次数

例如：

10

表示：

JSON1
↓
JSON2 × 10

⸻

五、循环计数规则

只有 JSON2 的全部事件执行完成，才算成功完成一次循环。

例如 JSON2 有：

点击 1
点击 2
点击 3
点击 4
点击 5

必须执行：

1
2
3
4
5

全部完成后：

循环次数 +1

如果在第 4 步停止：

不计入一次完整循环

⸻

六、执行示例

假设输入：

JSON1 = 登录并进入目标页面
JSON2 = 执行一次测试操作

循环次数：

100

那么程序执行：

执行 JSON1
    ↓
JSON1 完成
    ↓
执行 JSON2
    ↓
完整完成 → 1/100
    ↓
执行 JSON2
    ↓
完整完成 → 2/100
    ↓
执行 JSON2
    ↓
完整完成 → 3/100
    ↓
……
    ↓
100/100
    ↓
任务完成

⸻

七、停止操作

运行过程中可以点击：

停止

程序会请求停止当前任务。

停止后：

不会继续执行后续循环

当前尚未完整执行完成的 JSON2：

不会计入成功循环次数

九、鼠标移动

执行点击前，程序会先将鼠标移动到记录的位置。

例如：

记录坐标
↓
移动鼠标
↓
到达目标位置
↓
执行点击

移动时间会进行小范围变化，以避免所有移动时间完全一致。

⸻

十、注意事项

1. 屏幕分辨率

JSON 使用的是屏幕绝对坐标。

例如：

"x": 520,
"y": 340

因此录制和回放时最好保持：

* 相同屏幕分辨率
* 相同 Windows 缩放比例
* 相同窗口位置
* 相同软件界面布局

否则点击位置可能发生偏移。

⸻

2. 窗口位置

如果目标软件窗口位置发生变化，之前记录的坐标可能不再对应正确按钮。

建议：

录制时窗口位置
=
回放时窗口位置

⸻

3. 软件界面变化

如果目标软件改变了：

* 窗口大小
* UI 布局
* 按钮位置
* DPI 缩放
* 页面结构

可能导致点击位置不正确。

⸻

4. JSON 修改

可以手动修改 JSON。

例如：

{
  "type": "click",
  "x": 520,
  "y": 340,
  "button": "left",
  "delay": 0.82
}

可以修改：

"x": 600,
"y": 400

但修改前建议备份原文件。

⸻

十一、故障排查

程序无法启动

确认：

json.exe
auto.exe

是从 Windows 系统运行的有效 .exe 文件。

⸻

点击位置不正确

检查：

Windows 分辨率
Windows 缩放
目标窗口位置
目标窗口大小

是否与录制时一致。

⸻

JSON 报错

确认输入的是完整 JSON，例如：

{
  "version": 1,
  "mode": "json2",
  "events": []
}

JSON 必须符合标准格式。

特别注意：

{
}

和：

[
]

不能混用。
